# Phase 4: Multi-Scenario Decomposition Engine

## Overview
Phase 4 is the core intelligence of the platform. It uses the enriched graph to mathematically and logically propose different ways to split the monolith into microservices.

## 1. Strategy Algorithms (FastAPI)
Implement four distinct decomposition generators:
- **Aggressive Split:** Uses community detection algorithms (e.g., Louvain in Neo4j) to maximize the number of services based purely on weak coupling.
- **Conservative Split:** Groups larger clusters of nodes together to minimize network hops, creating fewer, larger services (Macroservices).
- **Domain-Driven Split:** Relies heavily on the `BELONGS_TO_CONTEXT` edges generated by the LLM in Phase 3 to map 1:1 with business domains.
- **Team-Driven Split:** Requires user input regarding team size/structure to partition the graph so that no service requires ownership by multiple teams.

## 2. Conflict Resolution & Validation
- **Circular Dependency Check:** Run a cycle-detection algorithm on the proposed service boundaries. If Service A -> B and Service B -> A, flag it as a critical violation.
- **Database Partitioning Check:** Ensure that if a table is split across domains, a data replication or API lookup strategy is flagged.

## 3. Saving Scenarios (PostgreSQL & Neo4j)
- Store the mathematical boundaries of each scenario in PostgreSQL as JSON objects.
- In Neo4j, create a temporary sub-graph for the user's active session to allow rapid querying of the proposed split without altering the base monolith graph.

## 4. API Endpoints
- Expose `GET /api/projects/:id/scenarios` to serve the 4 strategies to the frontend with high-level metrics (e.g., "Scenario A: 12 Services, High Complexity").
