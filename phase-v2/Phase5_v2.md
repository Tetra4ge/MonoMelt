# MonoMelt v2: Phase 5 (React Frontend Dashboard)

## 1. Phase Overview

Phase 5 transitions the project from backend data processing to user-facing presentation. The React frontend is the primary "Source of Truth" for the generated architectural reports. While Phase 6 will handle exporting data to Notion, the internal MonoMelt dashboard must provide a rich, interactive, and visually stunning representation of the JSON data generated by the Python AI Service.

This phase requires building a new routing view, implementing state management for HTTP polling, and constructing highly polished Tailwind CSS components to render complex matrices and financial data.

This document serves as the comprehensive, 150+ line technical specification for executing Phase 5.

---

## 2. Architectural Objectives

### 2.1 Polling & State Management
Because the backend report generation (Phase 3) takes ~15 seconds and runs in the background, the React frontend must handle a "Pending" state gracefully. We will utilize `react-query` (specifically `useQuery`) configured with a `refetchInterval` to ping the API Gateway every 3 seconds until the backend returns a `completed` status.

### 2.2 Component Driven Design
The report JSON is deeply nested. To prevent creating a massive, unmaintainable React component, the dashboard must be split into distinct sub-components:
*   `<ExecutiveSummary />` (LLM output and top-level metrics)
*   `<DecompositionGrid />` (Cards showing the microservice splits)
*   `<CostProjectionsChart />` (Recharts bar charts comparing monolithic vs microservice costs)
*   `<RiskMatrix />` (Warning flags and mitigation strategies)

### 2.3 Premium Aesthetics
As defined in the core MonoMelt UI guidelines, the design must feel premium. We will avoid generic colors and instead use glassmorphism (via Tailwind's `backdrop-blur` and `bg-opacity`), smooth gradients, and subtle framer-motion micro-animations when the report components load.

## 3. Implementation Details

### 3.1 Routing Setup
First, register the new route in `frontend/src/App.tsx`.

```tsx

// Inside your Router component:
<Route path="/projects/:projectId/report" element={<ReportPage />} />
```

### 3.2 The Data Fetching Hook
Create a custom hook `useProjectReport` in `frontend/src/hooks/useProjectReport.ts`.

```tsx
import { useQuery } from '@tanstack/react-query';
import api from '../services/api';

export const useProjectReport = (projectId: string) => {
  return useQuery({
    queryKey: ['report', projectId],
    queryFn: async () => {
      const response = await api.get(`/api/reports/${projectId}`);
      return response.data;
    },
    // If the status is 'generating' or 'pending', poll every 3 seconds
    refetchInterval: (query) => {
      const status = query.state.data?.data?.status;
      return (status === 'pending' || status === 'generating') ? 3000 : false;
    },
    retry: 1
  });
};
```

### 3.3 Main Page Component (`ReportPage.tsx`)
This acts as the orchestrator for the sub-components.

```tsx
import React, { useState } from 'react';
import { useParams } from 'react-router-dom';
import { useProjectReport } from '../hooks/useProjectReport';
import { ExecutiveSummary } from '../components/report/ExecutiveSummary';
import { CostProjectionsChart } from '../components/report/CostProjectionsChart';
import { Loader2, ArrowUpRight } from 'lucide-react';
import api from '../services/api';

export default function ReportPage() {
  const { projectId } = useParams();
  const { data, isLoading, isError } = useProjectReport(projectId!);
  const [isExporting, setIsExporting] = useState(false);
  const [notionUrl, setNotionUrl] = useState<string | null>(null);

  if (isLoading) return <div className="flex justify-center items-center h-screen"><Loader2 className="animate-spin text-blue-500" size={48} /></div>;
  if (isError) return <div className="text-red-500">Failed to load report. Please try again.</div>;

  const report = data?.data;

  // Render polling state
  if (report?.status === 'generating' || report?.status === 'pending') {
    return (
      <div className="flex flex-col items-center justify-center h-screen space-y-4">
        <Loader2 className="animate-spin text-purple-500" size={64} />
        <h2 className="text-2xl font-semibold text-gray-200">AI is assembling your report...</h2>
        <p className="text-gray-400">Aggregating Neo4j and PostgreSQL metrics.</p>
      </div>
    );
  }

  const handleNotionExport = async () => {
    setIsExporting(true);
    try {
      // Trigger Phase 6 Notion MCP Route
      const res = await api.post(`/api/reports/${projectId}/export-to-notion`);
      setNotionUrl(res.data.notion_url);
    } catch (err) {
      console.error("Failed to export to Notion", err);
    } finally {
      setIsExporting(false);
    }
  };

  return (
    <div className="min-h-screen bg-[#0a0a0a] text-white p-8">
      
      {/* Header & Actions */}
      <div className="flex justify-between items-center mb-12">
        <h1 className="text-4xl font-bold bg-gradient-to-r from-blue-400 to-purple-500 bg-clip-text text-transparent">
          Architectural Transformation Report
        </h1>
        
        <div className="flex gap-4">
          {notionUrl ? (
            <a href={notionUrl} target="_blank" rel="noreferrer" className="flex items-center px-4 py-2 bg-gray-800 rounded-lg hover:bg-gray-700 transition">
              View in Notion <ArrowUpRight className="ml-2 w-4 h-4" />
            </a>
          ) : (
            <button 
              onClick={handleNotionExport} 
              disabled={isExporting}
              className="px-6 py-2 bg-white text-black font-semibold rounded-lg hover:bg-gray-200 transition disabled:opacity-50"
            >
              {isExporting ? 'Exporting...' : 'Export to Notion'}
            </button>
          )}
        </div>
      </div>

      {/* Grid Layout for Sub-components */}
      <div className="grid grid-cols-1 lg:grid-cols-3 gap-8">
        
        <div className="lg:col-span-3">
           {/* Passes the nested JSON payload down as props */}
          <ExecutiveSummary data={report.payload.executive_summary} />
        </div>

        <div className="lg:col-span-2">
          {/* Note: In a real implementation, you would write this component */}
          {/* <DecompositionGrid data={report.payload.decomposition_strategy} /> */}
          <div className="p-6 bg-gray-900/50 border border-gray-800 rounded-2xl backdrop-blur-md">
             <h3 className="text-xl font-semibold mb-4">Decomposition Strategy (Placeholder)</h3>
             <p className="text-gray-400">Map over report.payload.decomposition_strategy here.</p>
          </div>
        </div>

        <div className="lg:col-span-1">
          <CostProjectionsChart data={report.payload.cost_analysis} />
        </div>

      </div>
    </div>
  );
}
```

### 3.4 Data Visualization (Recharts)
For financial data, we use `recharts` to create a beautiful, animated bar chart comparing the old monolithic cost against the projected microservice cost.

```tsx
import React from 'react';
import { BarChart, Bar, XAxis, YAxis, Tooltip, ResponsiveContainer } from 'recharts';

export const CostProjectionsChart = ({ data }: { data: any }) => {
  if (!data) return <div className="text-gray-500">Cost data unavailable.</div>;

  const chartData = [
    { name: 'Monolith', cost: data.current_monolith_cost_monthly },
    { name: 'Microservices', cost: data.projected_microservices_cost_monthly }
  ];

  return (
    <div className="p-6 bg-gray-900/50 border border-gray-800 rounded-2xl backdrop-blur-md h-full">
      <h3 className="text-xl font-semibold mb-6">Monthly Cost Projection</h3>
      <div className="h-64">
        <ResponsiveContainer width="100%" height="100%">
          <BarChart data={chartData}>
            <XAxis dataKey="name" stroke="#888888" />
            <YAxis stroke="#888888" />
            <Tooltip 
              cursor={{fill: 'transparent'}}
              contentStyle={{ backgroundColor: '#1f2937', border: 'none', borderRadius: '8px', color: '#fff' }} 
            />
            <Bar dataKey="cost" fill="#8b5cf6" radius={[4, 4, 0, 0]} />
          </BarChart>
        </ResponsiveContainer>
      </div>
      <div className="mt-6 p-4 bg-purple-500/10 rounded-lg border border-purple-500/20">
        <p className="text-sm text-purple-200">
          Infrastructure Multiplier: <span className="font-bold">{data.infrastructure_multiplier}x</span>
        </p>
      </div>
    </div>
  );
};
```

## 4. Integration Hand-Off (To Phase 6)

With Phase 5 complete, the MonoMelt application is fully self-sufficient. Users can upload monoliths, wait for the AI pipelines to finish, and immediately view a visually stunning, real-time updated architectural report inside the React app.

However, the "Export to Notion" button currently calls an endpoint (`/api/reports/:projectId/export-to-notion`) that has not been fully implemented in the Node.js backend. 

In **Phase 6** (the final phase), we will implement that Express route. We will build the translation utility that converts our JSON schema into Notion's strict Block API structure, and we will finally integrate the Model Context Protocol (MCP) to securely push that structured document directly into the user's connected Notion workspace.
